# Roles & Permissions Matrix

## Daftar Role

| Role | Deskripsi |
|------|-----------|
| `super_admin` | Pemilik platform. Akses penuh, termasuk kelola admin & konfigurasi sistem. |
| `admin` | Operasional harian lembaga: verifikasi pembayaran, approval cuti, kelola course, handle request guru. |
| `teacher` | Pengajar. Bisa mengajar kelas reguler dan/atau murid privat. |
| `student` | Murid. Bisa ikut privat, kelas reguler, self-paced, dan kajian umum. |
| `parent` | Wali murid anak-anak. Terhubung ke 1+ murid via parent_students. |

> **Catatan:** Satu user BISA punya lebih dari satu role (contoh: seseorang
> jadi `teacher` di privat dan `student` di kelas Tahfizh). Sistem harus
> mendukung multi-role per user.

## Aturan Owner-Scoping (WAJIB diimplementasikan di API layer)

1. Guru HANYA bisa melihat/mengubah data murid yang terdaftar sebagai
   murid privatnya (relasi via sessions/private_recurring_schedules).
2. Parent HANYA bisa melihat data murid yang ter-link di parent_students.
3. Student HANYA bisa melihat data miliknya sendiri.
4. SEMUA endpoint harus memvalidasi: role + ownership sebelum eksekusi.
   Jangan pernah mengandalkan penyembunyian UI saja.
